## 2. 最近一次改动：MV 首次打开黑屏

### 现象

第一次打开带 MV 的歌曲时，声音已播放但画面黑屏、没有视频帧；退出/重新进入后有时恢复。该问题仍需冷启动实测确认，不能宣称已完全解决。

### 当前判断与修复

Windows 原生视频纹理在更换媒体源时被重新 Key/rebuild，音频已经开始而原生 compositor surface 可能被短暂 detach，导致首开黑屏。

已修改：
`lib/features/player/presentation/now_playing_page.dart`

- 移除 `_mvSurfaceEpoch` 和用 `ValueKey` 强制重建 `Video` 的逻辑；视频 widget 保持挂载。
- 删去旧的“等到首帧后再次重建”的流程，改为在稳定 widget tree 的下一帧标记 surface ready。
- `_openMvSource` 先切到 MV 模式、等待一帧挂载视频 surface，再调用 `switchTrackSource`；平台 texture 等待最多 3 秒，超时后继续打开而不重建视频 view。

### 已验证

```powershell
flutter analyze lib\features\player\presentation\now_playing_page.dart
flutter build windows --release
```

均已成功（构建中有 Visual Studio 中间目录提示，不影响成品）。

### 下一位必须做的实测

1. 完全退出 Sona。
2. 从桌面 `Sona.lnk` 冷启动。
3. 立即连续打开多首 MV，尤其第一首；观察首帧、音画同步、进度条和切歌。
4. MV → 音频 → MV、自动下一首、从主页底栏返回播放器，都要测试。
5. 若仍黑屏，优先记录 video controller 的 platform/initialized/first-frame 状态；不要再通过不断重建 `Video` widget 来“修”。

## 3. 已实现/已反复调整的电脑端方向

- 整体视觉改为接近手机端的液态玻璃、主题壁纸和过渡动画；电脑端可一张背景贯穿，但缩略图和选择器也必须同步更新。
- 桌面图标改为手机端同款透明主体图标，快捷方式名称应为 `Sona`。
- 主题壁纸已批量适配电脑横向展示；`紫雾星环`应偏自然薰衣草、去掉丑的气泡/土星感；`耀石光环`增加岩浆；`醉红夜幕`提升皮革质感。
- 歌单总页已改为横向液态玻璃条目；歌单详情应替换主页面打开，而不是老式弹窗。
- 侧栏头部/底部固定、中部滚动；设置和账号不能被常用歌单顶走。滚动条需要与液态胶囊错开。
- 底部账号入口已要求：已登录显示头像+名称，未登录显示登录提示；点击必须跳“账号与云同步”二级页。
- 歌曲右键菜单、批量管理、播放器队列/循环、MV 页面、播放位置恢复等已经多轮改过，仍须按第 5 节做回归。

## 4. 视觉与交互的硬性要求

### 对比度与主题

- 每个主题、每个页面都必须可读，尤其深色主题的标题栏、Sona 文案、窗口最小化/最大化/关闭、侧栏、播放器按钮、歌单详情右上角按钮。
- 不能用“整页洗白”解决可读性；玻璃必须保持主题色调，只通过主题派生的浅/深玻璃层、文本前景色、描边/阴影提高对比度。
- 听歌排行目前的“随背景融合、仍可读”方向较好；曲库、收藏、歌单详情等需对齐这个原则。
- 歌单详情中“添加歌曲、编辑”是强调色；其余图标也必须有同等级可见性，不能发黑消失。

### 响应式

- 适配 14 寸到 24 寸、窗口缩放和全屏；不得依赖固定尺寸。
- 播放器标题必须单行省略，不能被挤成两行；操作区不得乱挤。
- 设置二级页、外观主题宫格应合理占用可用空间并根据宽度改变列数/卡片宽度。
- 播放栏与上方内容保留一小段视觉间距。

### 动画性能

- 侧栏切换页面、右键菜单弹出、播放器内切换皮肤仍是重点性能风险。
- 避免每次交互重建整页背景、重复 `BackdropFilter`、大范围 `setState` 或销毁/重建视频纹理。
- Overlay/菜单只动画自身（opacity/transform），背景遮罩尽量轻；页面切换不要与昂贵壁纸解码同时发生。

## 5. 必做功能回归清单

### 导航与歌单

- 所有左侧一级入口必须回到对应一级页：点击“我的歌单”永远回歌单总页；点击“设置”永远回设置根页；不能停留在先前的详情/二级页。
- 点侧栏某个常用歌单：主区域替换为该歌单详情；返回后恢复歌单总页。
- 新增歌曲到歌单必须按歌曲 ID/路径查重，重复要提示且不能重复插入。
- 多歌单间的数量、内容不能串台；曾出现“所有侧栏歌单瞬间都变成 6 首/返回后歌曲消失”的严重状态污染，必须修复并回归。
- 我的歌单页需支持右键管理；具体歌单详情/曲目也支持歌曲右键。
- 歌单排序管理暂未实施，用户要求先讨论：建议提供“最近创建、歌曲数量、名称 A-Z、手动排序”。

### 曲库与歌曲操作

- 批量管理必须有删除/从本地曲库移除。
- 右键歌曲根据来源展示正确操作：收藏/取消收藏、加入歌单、从最近播放删除、从听歌排行删除、从本地曲库移除。
- 删除歌曲后，当前播放、队列、收藏、最近播放、排行、歌单引用均不可残留坏数据；删除当前曲目时安全停播或切下一首。
- 早期导入歌曲曾出现播放时长 0 秒，新导入正常；需用旧数据回归确认元数据和媒体路径迁移逻辑。

### 播放器

- 底栏打开/关闭播放器、页面来回切换时，必须保留当前曲目、暂停状态和精确位置；曾出现返回播放器从 0 秒重播的严重问题。
- 自动下一首必须检测下一首类型：有 MV 用 MV 播放器，无 MV 用唱片播放器；不得对音频曲显示“没有配对 MV”。
- MV/唱片间切换不能重置同一曲目的播放时间。
- MV 页保留播放模式（列表循环/单曲循环等）和播放队列；这些功能此前被意外丢失。
- MV 时间轴可拖动、与视频同步；点击视频本体不要作为暂停交互。
- 无歌曲状态底栏应保持之前平衡、清晰的布局，不能只剩空控制区。
- 唱片页只保留一个音量入口：移除重复喇叭；音量条应更长、居中且不遮挡其它控制。
- 播放器设置需要“自定义定时/睡眠定时”。

### 云同步

- “账号与云同步”建议拆成两个玻璃模块：账号资料（名称、头像、退出）与云同步（预览、立即同步、云状态）。
- 用户要求可查看并管理云端歌曲/数据，能删除不需要的云端项目。该能力需同时考虑手机端，但可先完成桌面端数据模型/API/界面。

## 7. 接手时的注意事项

- 不要把“看起来能显示”当作完成，所有改动都要在至少浅色、深色、暖色、冷色主题下检查。
- 每次构建后必须更新桌面快捷方式并自动重启最新版本。
- 对播放器和数据库操作优先维护单一状态源；很多历史 bug 本质是页面状态、播放控制器、歌单数据各自缓存不同步。
- 任何涉及 MV 的修复都要避免销毁/重建 Windows 原生视频输出 widget，否则很容易重新引入首开黑屏和位置重置。
